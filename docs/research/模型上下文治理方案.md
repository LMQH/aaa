# 模型上下文治理方案

> 面向自研 Agent Harness 的上下文治理设计
>
> Harness = Provider + Tools + AgentLoop + Context + Boundary
>
> 本方案细化 Context 组件，并给出与之耦合的记忆契约与治理边界。

## 一、上下文构成

### 1.1 提示词分层切片

编号即组装顺序，自 1 至 10 变化频率大致呈现递减趋势。

| # | 类目 | 口径 |
|---|---|---|
| 1 | **Base Prompt** | 内置提示词本体，六个具名模块封闭枚举：SOUL → GUARDRAILS → RULES → TOOLS → AGENTS → ENV |
| 2 | **Built-in Tools** | 内置工具 schema，两组——最简内置面：`read` `bash` `powershell` `edit` `write` `grep` `find` `ls`；扩展内置面（条件插槽，实装才序列化）：`skill` `memory` `todo` `web_search` `web_fetch` `browser` `lsp` `pty` `jobs` `session_query` `subagent` `computer_use` |
| 3 | **Custom Tools** | 用户自定义工具的声明与参数 schema，随 `tools` 字段发送，不进 Base Prompt。两档：**直传 schema**（默认）与**目录化**（工具过多时只留一行目录，schema 经元工具取回） |
| 4 | **Skill Injections** | 技能索引：只含 name + description，常驻 system 前缀，低频易变（技能增删时才变）；技能正文不在本类。技能总成本 = 本类索引 + 第 8/6 类的正文 |
| 5 | **Injected Context** | 系统注入内容：事件驱动随行内容（插件、hook、runtime 注入块）＋ **记忆注入**（本地 Memory.md 与外部召回同等地位，不分离）＋ 压缩摘要（`compaction`）。随行内容锚定触发事件、带来源标签、可逐条下钻；压缩摘要（含工具结果微压缩）属替换，其余均为追加（见公理 2） |
| 6 | **User Messages** | 用户消息本体及其显式引用的上下文；用户显式调用技能时，技能正文作为用户消息计入本类；内联附件单独估算（记录类型与尺寸） |
| 7 | **Tool Calls** | 模型发起的工具调用：工具名 + 参数（重放部分） |
| 8 | **Tool Results** | 工具返回结果本体，按工具名细分、下钻到单次调用的状态与正文；模型调用技能时，正文经工具加载的结果计入本类（`read` 读 SKILL.md 或专用 `skill` 工具）；知识召回一律经工具取回，结果计入本类；知识库的组织形态（目录、摘要、分层）与检索质量属知识工具职责，本方案只约束取回结果的截断与可追溯 |
| 9 | **Reasoning** | 助手思考/推理文本 |
| 10 | **Answers** | 助手回复正文（扣除 Reasoning 与 Tool Calls） |

### 1.2 组装机制

各层在请求三字段中的落位：

| 层级 | system | messages | tools |
|---|---|---|---|
| 1 Base Prompt | 放 | — | — |
| 2 Built-in Tools | — | — | 放（schema） |
| 3 Custom Tools | —（目录化时一行） | — | 放（schema） |
| 4 Skill Injections | 放（索引） | — | — |
| 5 Injected Context | — | 放 | — |
| 6–10 | — | 放 | — |

### 1.3 装配约定

1. **渐进披露**：技能三级——索引常驻 system → 正文经工具按需加载（`read` 读 SKILL.md 或专用 `skill` 工具）→ 引用文件由模型自读；工具两级——默认直传 schema → 超阈值改一行目录，由元工具取回。
2. **指引随工具定义**：工具使用指引由工具定义自带，组装时汇出；自定义工具指引随 schema description。
3. **自定义工具必须可执行**：以代码插件或 MCP 定义，不设声明式 JSON/YAML 工具 DSL；配置面只管装载启停。
4. **前缀稳定**：静态本体与低频常驻内容构成缓存前缀，高频可变内容一律后置或走消息侧。
5. **快照追加式**：快照随通道存在，无通道不注入；变更以新快照声明覆盖旧快照，旧快照不清除、永久留史，由压缩统一吸收，不设独立回收。
6. **时效标注**：过期快照自带时效声明，声明只进新快照，不回改旧快照。
7. **注入贴事件**：随行注入锚定触发事件（用户提交、工具结果、状态变化），不设统一槽位；用户消息本体不改写，除最后一条用户轮外可参与压缩（公理 6）；记忆召回作为系统注入计入第 5 类，用户显式引用随消息进入历史。
8. **结果随工具定义**：工具声明输出的 schema 与渲染，未声明者原样透传；runtime 只附注，附注带隔离标签。
9. **推理双面分离**：存储面全存，推理块随 assistant 条目落史；重放面按结构规则回传（如仅含工具调用的轮次回传推理块），普通轮默认剥离；预算面只计重放面（定理 6）。
10. **生命周期为配置**：冷启动装载、分支/分叉、会话归档的执行时机与开关由配置决定，不作为治理规则；其产物仍受本方案约束——分支摘要按压缩（定理 3），归档后的巩固按 2.3 第 4 条。

## 二、治理策略

### 2.1 公理与定理

> 公理 1–6 提炼自 omp、Claude Code、Hermes、Pi、DeepSeekHarness 五个实现的共性交集，属已收敛的业界默认，直接作为基线采纳。

**公理**（不可违反的基础不变量）：

1. **存储只追加**：会话以只追加的条目流持久化，条目类型封闭（`message` / `compaction` / `summary` / `custom`，新增须修订本公理）；记忆条目属引擎侧对象，不进入会话条目流（见 2.4）。治理不改写、不删除既有条目，效果只表现为新增条目；被移出视窗的原文不得丢失——仍在条目流内，或由该条目声明的外部全文存储持有且引用可解析。会话删除、保留期清理、归档等存储生命周期动作不属于治理，不受本公理约束。
2. **改动只有四类**：视窗每轮由条目流重建，允许的改动只有四类——
   - **追加**：新条目进入视窗；
   - **剔除**：内容不进视窗，存储不动，粒度为整条、内容块或字段（剥离推理块、旧快照不再注入、非视觉模型丢图片）；
   - **替换**：单条内容在视窗内只以预览加指针出现，全文须可解析（工具结果截断、超限落盘回注）；
   - **压缩**：连续一段历史换成一条摘要，须记录首个保留条目与被压缩区间的引用；摘要可被后续压缩吸收，被吸收者保留引用。

   四类之外即违规：就地改写、无引用丢弃、把重建结果写回条目流。
3. **循环不可分**：未闭合的工具循环整体不可治理；压缩切点不落在 tool-call 与 tool-result 配对之间，保留尾以用户轮为边界。
4. **有界性**：自动治理必须可终止——溢出重试有上限、摘要失败有冷却、压缩持互斥锁并可识别崩溃孤儿、连续无进展即暂停自动治理。
5. **供应商中立**：跨供应商序列化差异（推理块回放、字段命名、原生压缩）收敛于 provider 适配层，治理策略层不感知模型供应商。
6. **用户消息参与**：用户消息不豁免治理；仅最后一条用户轮保活原文。
7. **成本三因子**：上下文成本逐条由三个因子相乘、再沿会话累加构成——内容体积、该内容在视窗中的剩余驻留轮数、单价（随模型与缓存命中状态而变）；体积是截面量，成本是积分量；任何治理动作必须声明它改变哪个因子、预期改变多少，无法归因到某一因子者不进入治理策略。

**定理**（由公理导出的操作规则）：

1. **双旋钮预检**：预检有两个独立旋钮，分别对应公理 7 的两个因子——**溢出阈值**：按窗口比例，门控压缩及其后继兜底，溢出错误仅作有界兜底，无滞后带，防抖由进展门与冷却承担，此旋钮不承担成本治理；**驻留预算**：独立于溢出阈值，按成本口径设定（默认取窗口的四分之一量级），触发条件不是体积本身，而是「可回收量 × 剩余轮数 × 缓存折扣 > 重建量」（见缓存敏感提交）。剔除在序列化时按各自规则生效；替换在产出端与驻留期均可生效。
2. **尾部保留**：全量压缩只作用于头部区间，最近尾部按预算原文保留。预算以「轮」为口径——保留最近 K 轮原文，体积上限为驻留预算的四分之一，超出则减少轮数直至满足。压缩以新增压缩条目表达，被压缩区间原文留在条目流中。切点落在某一轮内部时向该轮轮首回退；回退后仍超预算时，对该轮前缀单独压缩，形成第二条摘要。此路径是兜底：若它成为常态，说明入口上限与尾部预算不同尺度（见入口硬上限）。
3. **摘要规范**：摘要为单条专用条目，以 user 角色承载但不参与「最后一条用户轮」的判定；置于保留尾之前、system 之外。固定节结构；输出有独立预算，被截断即失败。输入为投影而非原文（工具结果、工具参数、推理块各有字符上限，且投影上限不低于摘要输出预算）。提交前不校验收缩量，而校验净收益——`收缩量 × 剩余轮数 × 缓存折扣 > 重建量`。压缩区间必须覆盖此前产生的全部摘要，使摘要不随压缩次数累积。
4. **成本阶梯淘汰**：驻留预算被突破时，按信息损失升序逐级触发——机械剪裁 → 替换（工具结果与参数降级为预览）→ 压缩（全量压缩）→ 丢图片。前三档分别对应公理 2 的剔除、替换、压缩；第四档是剔除在字段粒度上的形态，因信息不可复原而置于末位。各档的真实代价取决于是否重写已缓存区域：重写历史区的动作（替换、压缩）承担前缀重建，判据同缓存敏感提交；仅作用于产出端、不触碰已缓存区域的动作才可视为更低一档。低阶未解决才进入高阶。本阶梯只作用于体积因子，轮数与单价不在其管辖内；换更大窗口模型只改变溢出阈值，不是治理动作。
5. **剔除优先级**（成本阶梯在剔除动作上的细化）：候选先过三道筛再定序——**可复原性**：能从存储取回或不影响结论者优先；**可执行性**：受 provider 回放约束而无法剥离的字段不进入候选（公理 5）；**体积收益**：按公理 7 的积分计，收益大者优先。过期快照与旧召回内容先于图片；推理块仅在 provider 不强制回放时进入候选；旧工具结果原文的位次由积分决定，不预设为末位。剔除若改变已缓存区域，应与本轮其他动作合并提交，避免重复付重建代价。
6. **混合计量**：一切计量以视窗投影为对象，不以条目流或产出端原始尺寸为对象——估算输入必须是投影后的内容，凡发生截断、替换、降级的位置一律计投影量。以 provider usage 为锚；usage 缺失的字段（如不上报的缓存写入）以启发式补足并在事件记录中标明来源。基线 chars/4 仅适用于主体区间，超限区间与代码、日志等稠密内容按内容类型分档修正。图片按定额计价。CJK 稠密字符加权修正。
7. **索引常驻正文按需**：技能索引（name+description）常驻，正文按需加载；工具目录在 schema 数量超过阈值时改为一行目录，经元工具取回，核心工具白名单按实际调用覆盖率确定，不按固定名单；基础提示词受同一预算约束，按模块核算并纳入静态前缀总预算。
8. **入口硬上限**：工具结果与工具调用参数在产出端设同一形态的硬上限（同一阈值、同一落盘格式）；超限即截断，全文落外部全文存储，视窗只留预览，截断处回注 cap 与续读方式。本规则是防止单条内容挤爆视窗的安全阀，不承担成本治理——它只作用于极端长尾。
9. **驻留降级**：替换不限于产出端。任一内容的已驻留轮数超过 K（与保留尾共用同一边界）时，降级为定长摘要加可解析指针，原文留在外部全文存储，与产出端截断同格式、同回注方式。入口上限已约束单条体积，故此处按轮数判定，不另设体积阈值。
10. **缓存敏感提交**：提交指本轮视窗配置定稿并发出请求，永不写回条目流。提交前按净收益判定——`回收量 × 剩余轮数 × 缓存折扣 > 重建量`，不满足则推迟本轮提交；同一轮内的剔除、替换、压缩必须合并为一次提交，避免重复付重建代价。清理时机避开 provider 缓存 lookback 窗口。

### 2.2 参数定案

| 参数 | 共识默认 | 定案 |
|---|---|---|
| 溢出阈值 | 窗口 75%–85%（小窗口需更保守） | `W − max(15%×W, 16384)`；不扣输出上限，溢出由恢复路径兜底；只防崩溃，不控成本 |
| 驻留预算 | — | `W/4`；独立于溢出阈值，下限须大于「静态前缀 + 2×保留尾」，否则压缩后立即再触发 |
| 保留尾 | ≈20,000 token 或窗口 15%–16% | 最近 K 轮，体积上限为驻留预算的 1/4（= `W/16`）；K 默认 15 |
| 摘要输出预算 | 8k–13k token | 10,000 token |
| 工具结果与参数上限 | ≈50KB / 2,000–3,000 行 | 安全阀，与驻留降级阈值分开配置；超限落外部全文存储，预览 2KB |
| 驻留降级阈值 | — | 驻留轮数 > K 即降级，与保留尾共用同一边界 |
| 目录 listing 预算 | ≈5%×W | 5%×W |
| 溢出重试上限 | 1–2 次 | 1 次 |
| 召回注入预算 | — | 条数上限 ≤ N，token ≤ 2%×W |

默认值可按模型覆盖。

实现取向：单层结构——入口上限 + 驻留降级 + 全量压缩 + 溢出恢复即最小完备形态；成本阶梯各档允许合并，不要求独立微压缩层与独立回收层。

**观测指标**（建议默认，运营可调）：

| 指标 | 口径 | 建议默认 |
|---|---|---|
| 估算偏差 | 估算值与 provider usage 的偏差率（usage 有效时按增量计） | ≤10%；>20% 告警 |
| 缓存命中率 | `cacheRead / (input + cacheRead + cacheWrite)` | ≥70% |
| 压缩达成率 | 自动压缩一次后上下文 ≤ `80%×T` 的比例 | ≥90% |
| 治理事件记录 | 每次压缩/剪裁/替换携带：类型、原因（`manual`/`threshold`/`overflow`）、前后 token、方法 | 覆盖率 100% |
| 驻留成本归因 | 以视窗投影为准，逐条累计 `体积 × 驻留轮数`（token·轮），按类目与工具名聚合，可下钻至单条；金额 = 积分 × 当期单价，单价取自 provider 定价表，不在治理层固化 | 每会话产出，Top-5 条目可下钻 |

前三项为治理质量指标；后两项是它们的数据源，属必须实现的基础设施，非可调目标。

**行为指标**（验证规则是否生效，不作质量目标）：

| 指标 | 口径 | 判读 |
|---|---|---|
| 截断命中率 | 触发截断的结果数 / 结果总数 | 长期接近 0 属正常——入口上限是安全阀；持续上升说明长尾变厚，应回到入口侧治理 |
| 降级命中率 | 触发驻留降级的内容条数 / 内容总条数 | 与平均驻留轮数对照：降级已生效而驻留仍高，说明预算设得过松 |
| 召回注入占比 | 第 5 类记忆注入 token / used | 对照 2.2 预算，超出即预算未执行 |
| 压缩频率 | 每 100 轮的自动压缩次数 | 异常上升说明阈值偏紧或内容膨胀 |
| 前缀失效率 | 前缀哈希变化次数 / 请求数 | 应只随静态本体变更发生，否则"前缀稳定"已被破坏 |
| 平均驻留轮数 | 每条内容自进入视窗至离开（压缩、剔除、会话结束）的轮数，按类目与工具名取均值 | 高则该类成本集中在"驻留久"，由替换与压缩处理；低则入口截断已足够 |

### 2.3 记忆契约

主体：harness。以下四项是 harness 必须提供的行为。

1. **条目**：记忆是带元数据的条目，至少含 `id`、`kind`（事实／偏好／约束／任务／决策／纠正）、`value`、`revision`、`status`（有效／已覆盖／已删除）、`source`（来源会话与依据消息）、`updatedAt`。覆盖以"新条目声明覆盖旧条目"表达，旧条目留史不删。
2. **工具面**：读写只经内置 `memory` 工具，操作集为 `search`（按查询检索）、`get`（按 id 取全文）、`propose_update`（提案写入：create／update／supersede／expire／delete）、`forget`（作废）。写入与作废必须携带期望版本，未命中即失败并返回最新状态；软删即时生效，硬删需确认。
3. **注入面**：一切记忆注入归第 5 类 Injected Context；本地 Memory.md 与外部召回地位相同，不分离、不另设类目。注入按类别分节（约束／任务／偏好／摘要），每条带来源、时间与可下钻引用，受条数与 token 双重预算（见 2.2）；自动召回为空不得视为无记忆，应以 `search` 复核。
4. **巩固面**：巩固由独立请求完成，只带记忆工具、不带其他工具与应用数据；输入为投影而非原文；产物可审计（依据哪些消息、由谁写入、何时）。同一时刻只允许一个巩固方。

### 2.4 记忆引擎

主体：引擎与边界。本节只描述引擎侧，不重复 2.3 的义务。

1. **定义**：引擎是以记忆条目为对象、只经四个交互面被使用的持久化与检索组件——**写入**（带期望版本的提案）、**读取**（按 id、按查询、按层级）、**变更留痕**（新增、覆盖、作废；引擎内部行为，不对模型暴露）、**生命周期执行**（删除或过期）。内部实现（索引、重排、提取模型、巩固管道、TTL）不构成职责。
2. **可替换**：引擎与契约解耦。替换引擎只替换实现，不变更工具面、注入面与巩固面，也不得触发公理或定理的修改。
3. **边界**：记不记、取几条、何时忘、注入到哪里由 harness 决定；存在哪、如何找回、如何留痕由引擎负责。引擎不得自行改变投影，其变更以"新条目 + 声明覆盖"进入投影；自带压缩必须关闭（公理 2）。
