# Harness 最小实现公式模型与闭环实现准则

## 1. 核心公式

> **Harness = Provider + Tools + AgentLoop + Context + Boundary**
>
> **由 AgentLoop 驱动，利用 Context 调用 Provider 与 Tools，并由 Boundary 约束整个执行过程。**

本公式作为 Harness 最小实现的职责模型与闭环实现准则。这里的“+”表示职责协作，不要求实现为五个独立模块。

本文将 Harness 定义为：驱动模型持续推进任务，并管理模型接入、工具执行、上下文和执行边界的运行系统。

## 2. 五项最小职责

| 组成 | 核心问题 | 最小职责 |
| --- | --- | --- |
| Provider | 如何调用模型？ | 适配模型请求、响应和工具调用协议，将模型输出交给运行循环处理。 |
| Tools | 能采取什么行动？ | 声明可用工具，执行工具调用，并返回执行结果或失败信息。 |
| AgentLoop | 如何持续推进？ | 调用模型、处理输出、调度工具、接收反馈，并决定继续或结束。 |
| Context | 每一步凭什么判断？ | 组织指令、任务输入、历史、工具结果及必要的运行状态，构造下一步模型输入。 |
| Boundary | 哪些行动可以发生，运行到哪里结束？ | 强制执行权限、资源限制和终止条件，约束整个执行过程。 |

### 职责解释

- **Provider 是模型接入层。** 模型及其服务是外部依赖，Harness 负责接入与适配。
- **Context 包含必要的运行状态。** 最小实现中，任务进度、待执行调用、停止原因等状态可以与上下文一起管理；复杂实现可以再拆出 State。
- **Boundary 必须由运行代码执行。** 提示词可以表达限制，但权限检查、调用次数上限、超时和停止控制等边界必须在相应执行点生效。

## 3. 最小闭环

```text
接收任务
   ↓
组织 Context
   ↓
Boundary 检查是否允许继续
   ↓
AgentLoop 调用 Provider
   ↓
处理模型输出
   ├─ 最终回答 → 记录结束状态并返回
   └─ 工具调用
         ↓
      Boundary 检查是否允许执行
         ↓
      执行 Tools
         ↓
      将结果写入 Context
         ↓
      返回下一轮
```

Boundary 贯穿整个流程。图中的检查点用于说明关键位置；具体实现应在受约束的操作发生时执行对应检查。

工具执行失败或调用被拒绝时，应形成明确反馈，由运行循环决定继续还是结束。达到资源上限或终止条件时，循环必须能够停止，并返回明确的结束原因。

## 4. 最小实现准则

1. **模型可接入：** 能构造一次模型请求，并将响应转换为循环可以处理的结果。
2. **行动可反馈：** 当模型请求工具调用时，能够完成权限检查、工具执行和结果回传。
3. **循环可推进：** 工具结果能进入下一轮上下文，模型能够据此继续任务或给出最终回答。
4. **状态可衔接：** 每一轮保留推进任务所需的信息，明确当前是否继续及为何结束。
5. **边界可强制：** 被禁止的操作不能执行；达到设定的运行限制时必须停止。
6. **结果可返回：** 正常完成、执行失败和边界终止都具有明确的返回结果或结束状态。

这五项是最小职责集合。Tools 可以为空集，AgentLoop 可以只运行一轮，Boundary 可以采用固定限制；不要求为了符合公式增加独立模块或配置系统。

## 5. 扩展能力的归属

Memory、Skills、MCP、多 Agent、持久化、可观测性，都可以作为五项的扩展或横切能力，不必为了最小实现继续增加一级概念。

下表表示常见归属，具体实现允许跨越多项职责。

| 扩展能力 | 在公式中的常见归属 |
| --- | --- |
| Memory | 为 Context 提供历史信息的存储、检索与更新能力。 |
| Skills | 向 Context 提供任务指令，向 Tools 提供可执行资源，并接受 Boundary 约束。 |
| MCP | 为 Tools 等能力提供接入协议；取得的资源可以进入 Context。 |
| 多 Agent | 扩展 AgentLoop 的调度与协作方式，并处理 Context 传递及 Boundary 继承。 |
| 持久化 | 保存 Context、运行状态和执行记录，支持恢复。 |
| 可观测性 | 跨越五项职责，记录调用、状态变化、工具执行和边界决策。 |

这些能力是否需要独立模块，由实际复杂度决定，不影响最小公式的成立。

## 6. 验收标准

最小实现应能够验证以下行为：

- **直接完成：** 接收任务后调用模型，返回最终回答并结束。
- **工具闭环：** 模型发出工具调用，工具结果进入下一轮上下文，模型据此继续或完成任务；此项适用于启用工具的实现。
- **边界阻止：** 对不允许的操作，在执行前拒绝，并产生明确反馈。
- **有界终止：** 模型持续请求继续时，达到设定的轮次、时间或其他资源限制后能够停止。
- **异常收束：** 模型或工具执行失败时，能够明确继续策略或结束原因，不会无条件无限循环。

**采用本模型时，以五项职责是否形成可执行、可反馈、可终止的闭环，判断 Harness 最小实现是否成立。**
