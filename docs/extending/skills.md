# 技能

技能是给模型的领域说明：一段 Markdown，模型按需读取，不执行任何代码。

## 位置与命名

- 用户目录：`~/.agents/skills/<技能名>/SKILL.md`
- 分类目录：`~/.agents/skills/<分类>/<技能名>/SKILL.md`（只支持两层）
- 随包目录：`aaa/builtin_skills/<技能名>/SKILL.md`
- 技能名取目录名；同名时先扫到的生效，用户目录排在随包目录之前，因此可以覆盖内置技能。

启动时扫描一次，改完要重启 aaa。

## 格式

```markdown
---
name: release-check
description: 发布前检查版本、锁文件与变更记录。用户说“发版”“打 tag”时使用。
---

# 发布前检查

正文写方法、约定与示例。模型看到的就是这一段，frontmatter 不会给它。
```

规则：

- frontmatter 由 `---` 包裹，只解析 `key: value` 与缩进续行。
- `description` 必填：它是 `/skills` 展示与模型判断“要不要读”的唯一依据，写清触发场景。
- 不要用 YAML 的块标量（`>`、`|`），解析器会把标记当正文，`/skills` 里会看到多余的符号。
- `name` 与目录名保持一致的目的是避免误解，索引实际用的是目录名。

## 模型怎么用它

- 系统提示词只列技能名与描述。模型按需调用 `load_skill(name)` 读取正文，不预载正文或引用。
- 把引用放进该技能的 `references/`，在正文中指引模型用 `load_skill(name, reference="guide.md")` 阅读。引用只接受单个 `.md` 文件名，文件名由 ASCII 字母、数字、连字符、下划线组成且以字母或数字开头；不能越出该目录。
- `references/` 必须是真实目录；引用文件不能链接到目录外。链接到技能目录外的 `SKILL.md` 不会被发现，读取正文时也会重新检查。
- `load_skill` 是只读工具，所有权限模式可用，不执行技能脚本。包内 `create-extension` 的引用随 wheel 提供，使用时不需要检出 aaa 源码。

## 查看

`/skills` 列出发现的技能与各自 description 的第一行。

## 创建方式

- 让 agent 调用 `create_skill(name=..., content=...)`，每次写入需要确认；同名已存在时默认拒绝，要覆盖须显式确认。
- 或直接建目录写文件。

## 生效

重启 aaa 后生效。技能不修改配置，不触发 Agent 重建。

## 与命令模板的区别

- 命令模板：用户显式输入 `/name` 才触发，正文直接作为消息发送。
- 技能：模型自己决定何时读取，正文按需进入上下文。
