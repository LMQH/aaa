# 备忘录

暂不执行、但需要保持可见的计划。每条写清「触发条件 / 做法 / 为什么现在不做」，做完即删，不留变更痕迹。

## 依赖升级时才开的新版本隔离期

- 触发：第一次 bump 任何一个 `pyproject.toml` 里的直接依赖（最可能是 agno）。
- 做法：加 `[tool.uv] exclude-newer = "14 days"`，让发布不满 14 天的版本不进解析；需要抢安全修复的包用 `exclude-newer-package` 单列豁免。这是 Hermes 的做法，针对的是「上游刚被投毒的版本在隔离期内无人复核就被装进来」。
- 为什么现在不做：它与「锁文件以当前实测版本为准」直接冲突——开启后解析会拒绝当前基线里的新包，锁结果偏离已验证环境。
- 升级动作一并约定：改 `pyproject.toml` 的 `==` → `uv lock` → `uv sync --frozen` → 重跑 `tests/e2e.py` 全套；重点确认 agno 的 `MemoryManager(model=, db=)`、`CodingTools`、`RunPausedEvent`/`continue_run` 三个面没变。

## 演进终点：成为 goal agent

**根本实现为 Agno**：所有方案以 Agno 3.1.12+ 生态为宿主，优先复用其原生机制（AgentOS 调度与后台任务、HITL 暂停续跑、tools 控制面、LearningMachine），自建只落在 Agno 的已证缺口处（Boundary 统一策略源、停止规则语义、结论性记忆、goal 契约）；不引入 Agno 之外的新组件承载已有机制。

- 触发：本项目从任务型 harness 向目标型 Agent 演进时启动；依据 `docs/research/从任务到目标的Agent架构演进.md` 与 `docs/research/从任务到目标的Goal设计方法.md`。
- 做法：四个阶段，顺序即依赖顺序——
  1. **Boundary 扩宽**：细粒度工具权限（按工具名 allow/deny，声明进 `config/settings.py` 键表，Loop 执行前经 Boundary 校验，衔接 Agno `include/exclude_tools` 与 HITL 标记）；触发器层以 AgentOS 后台任务与调度承载（心跳/周期 cron/一次性 cron/事件流映射到其调度形态，统一抽象为 trigger → 一次 run，Agent 可返回「无需动作」）；停止规则（「暂停/忽略 + 理由」作为与「任务完成」并列的终止语义）。
  2. **Context 补目标型记忆**：结论性记忆契约（跨运行持久化「已确认决策」与「被否决选择 + 理由」，loop 启动注入、反馈发生时写入；自建条目存储，不沿用 Agno 删除式记忆维护——Curator/MemoryManager 与「留史不删」相反）；后台提问不设独立收件箱组件，复用 Agno HITL 暂停态（`requires_user_input` + `active_requirements`）作为提问载体，答复表面沿用现有交互面（CLI/UI 读取暂停态 run），Slack 通知等仅作可选插件。
  3. **Goal 承载与反馈闭环**：Goal 声明契约（预期结果 + 边界 + 度量指标 + 反馈方式，类型化，不复用 task 输入）；自主任务拆解（发散 → 挑选 → 执行 → 更新对外可见清单，提示策略强制发散度）；反馈按「同类任务集中批量审阅、反馈迁移同范围」切分目标范围。
  4. **收敛**：目标型 Agent = AgentOS 触发调度 + goal 契约 loop + Boundary 策略源限权的 tools + 自建结论性记忆 + HITL 暂停续跑，全部落在 Agno 生态内，不另起第二套架构。
- 为什么现在不做：当前是任务型形态，权限与触发器没有后台运行场景牵引；但范式切换时其余组件不动，仅靠这四类接缝扩展即可，因此接缝设计（尤其 Boundary）在近期改动中保持不关闭。

## 佐助瞳术体系：概念映射与设计

**项目定位**：本项目是受《火影忍者疾风传》中宇智波佐助的战斗哲学与瞳术体系启示而进行的自研轻量级自主 Agent 运行时与 Harness 适配框架。

**映射结论**

- **写轮眼 → 洞悉 + 拷贝**：同一只眼的两个功能，不是两个能力。**拷贝（主位）**：委派定义的持久化与跨会话复用——会话里验证过的 Agent / Team / Workflow 定义经确认保存，新会话直接复刻执行；落在 `runtime/delegation` 与注册表，是产品主卖点。**洞悉（辅助）**：会话上下文占用诊断——只读观测面，内核暴露消息结构、usage 与注入清单，CLI 渲染分段 token；不参与上下文装配。原型参照 `dsh-context`。
- **天照 → 自主模式（默认 Loop 策略）**：Silent ReAct，能做的全做；遇可推迟决策只记录不阻塞，结束时批量返回决策单；停止语义含轮次、时长、无进展、重复动作。不可推迟项（不可逆、越权、缺授权）硬停或跳过，不得记录后续跑；被待决项阻塞的下游任务标记「待决」，不得按猜测默认值执行。
- **加具土命 → 人主导模式**：意图不清先澄清、不盲目执行；约束意图、范围与不可逆动作，不约束实现细节；两模式共用决策权分级表，仅默认档位不同。
- 两模式是同一条 Loop 上的两套控制策略，run 级选择，运行中不切换；默认模式持久化。
- **须佐能乎 → 待重新实现**：只保留概念——按需组合的能力层，未启用的层不注入提示与工具。具体映射作废重议：重新设计后再落 `DESIGN.md` 与代码，重议前不进入实现。
  - 待决：层在构造期组合还是运行期切换；与权限模式、`SYSTEM.md` 覆盖、自定义工具的优先关系；失败时回退到哪一层、是否显式提示。
  - 为什么现在不定：现有 `mode`（read-only / workspace-write / danger-full-access）与提示词覆盖已在做能力收窄，再加一层若说不出独立收益，只会多一套并行语义。
- **雷遁、火遁 → 暂不映射**：候选为双执行路径（雷=快速、确定、直达；火=探索、持续、生成），须有真实需求牵引；概念须有独立可测行为才进入代码命名。

**配套约定**

- 自主模式的决策单需跨会话保留（存会话库），否则下次启动丢失。
- 配置持久化白名单：默认模型、默认模式、审批策略、界面偏好写入 `config.toml`；当前任务、待决策队列、TODO、本轮模式属会话状态；运行中临时对象与暂停态不持久化。持久化键改名须提供迁移。
- 写轮眼口径固定：系统提示、工具 schema、历史、技能/记忆注入各占一段，估算 token 只在同口径间比较。

**执行结构（已定）**

- 执行体只有主 Agent 自身的 Loop；REPL 是交互主循环，不另设编排层。
- 接缝颗粒度到 `Agent.run`，不到 Agent 内部迭代：Agno 没有逐轮钩子，也不改 Agent 内部。分工：run 内轻量观察与拦截 → `pre_hooks`/`post_hooks`；单次工具调用 → `tool_hooks`；输入输出检查 → guardrails。同一职责只落一处。
- 后置 commit 门控：run 前记录 git 快照，门控只提交本 run 内变化且落在允许路径的文件，经 `HumanReview(requires_confirmation=True)` 审批；无法可靠归属时只输出建议 diff，不自动 `git add -A`；仅在 run 成功时进入，按逻辑阶段触发而非每次 run 无差别提交。

- 触发：进入实现阶段时启动；先按此映射落对应模块 `DESIGN.md`，再改代码。
- 做法：写轮眼的拷贝落在委派注册表（`runtime/delegation`），洞悉落在观测层；天照/加具土命落在 Loop 控制策略（含决策队列与依赖感知跳过）；须佐能乎待重新实现后再落设计；雷遁/火遁留空待需求牵引。
- 为什么现在不做：写轮眼、天照、加具土命的映射结论已定但均未进入实现；须佐能乎的映射待重新实现。先落设计再动代码，避免命名与边界锁定在错误抽象上。
