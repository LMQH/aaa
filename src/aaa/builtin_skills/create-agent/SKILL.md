# 创建可委派的 Agent

1. 从任务推导一个独立职责：说明要解决什么、接收哪些上下文、交付什么，以及怎样判断完成。把本次任务的数据和可复用的角色指令分开。
2. 按职责写指令，明确证据要求、不能处理的范围和遇到缺失输入时如何返回。成员角色与指令可以现场定义，不必从预设角色中挑选。
3. 模型、工具和权限只能从宿主已明确提供给调用方的选项中选择，且只请求职责所需的能力。宿主提供默认项时可沿用；缺少必要选项就标明依赖，不猜名称、不把提示词当授权。实际权限由宿主在装配和调用时检查。
4. 交付一份可审阅的定义草案：名称与职责、角色指令、输入、交付物与完成条件、需要的宿主能力。给 Team 内联成员使用时直接交付同一结构，不要求单独保存。只定义可委派的 Agno `Agent`，不替换主会话的执行体。

例如：兼容性审阅员接收改动范围和现有契约，只用宿主允许的读取能力，输出受影响调用方与证据；找不到依据时明确标为未验证。

调用 `list_delegations` 查看可选模型与工具。提交 `register_delegation(definition={"entry":"reviewer","definitions":{"reviewer":{"kind":"agent","description":"兼容性审阅","instructions":"列出受影响的调用方及证据","tools":["read_file"]}}})`；`model` 可省略以使用当前模型，`tools` 省略则不提供子工具。只填宿主实际列出的值。

注册成功后用 `delegate_task(tasks=[{"ref":"reviewer","input":"本次任务和必要上下文"}])`。定义默认临时；能说清下一次何时复用才提议 `save_delegation(definition=原定义)`；用户明确要求保存时直接提议。未获用户确认不算保存。
