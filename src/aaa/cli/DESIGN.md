# cli — 模块设计

## 设计铁律

**owner 决议原则，实现者在原则内选择具体机制，并在动手前反馈选择与理由、交付时报告偏差。** 新原则、跨模块取舍、呈现形态改变必须先获 owner 批准。

- **运行底座与 CLI 分开设计**：Agno 拥有执行循环与持久化；CLI 负责交互体验与丰富呈现，不把「内核极简」解释成「界面只能输出纯文本」。
- **已定形态**：主屏内联交互、保留终端滚动历史；Python + prompt_toolkit，不迁移全屏接管式框架。
- **遵循 Agno 原生历史语义**：含已取消运行的处理方式。凡需自造上下文回放层才能达成的目标不做，也不提供半成品命令。
- 交互启动默认播放品牌横幅；总边界见 [总架构](../../../docs/architecture.md)。

## 一、范围与交付边界

目标：在不接管全屏、不重写 Agno 的前提下，提供可打断、可排队、审批不抢输入、富文本与局部 diff 高亮、TODO 树形任务区、Git 状态与启动动画。

包含：输入与运行状态协调、命令统一分派、错误反馈、主屏渲染、状态条、TODO 呈现、工具详情、终端兼容与非交互隔离。保持既有命令名、权限模式、插件目录与重启生效约定。

不包含：新增 agent 执行循环、steering 注入、Vim/鼠标/语音、多窗格全屏应用、新插件协议、MCP 实测、发布部署。

## 二、外观

### 启动图案与品牌

- 启动动画是可替换的单文件单元：`cli/animations/<name>.py` 与 `~/.aaa/animations/<name>.py`，同名时用户目录覆盖包内；`cli/banner.py` 只做宿主，不含动画素材。
- 契约：模块级导出 `ANIMATION`。函数等同于 `frames(ctx)`；对象需有 `frames(ctx)`，可选 `min_columns`、`min_rows`、`static(ctx)`。`frames(ctx)` 每项产出 `Frame(delay, content)`，`content` 是字符串或 `columns -> 字符串`，绘制推迟到需要那一帧时。动画不接触终端。
- 宿主负责空间判定、按单调时钟调度并跳过已过期帧、缩窗中止、超宽行拦截，以及加载失败时回退单行标题；任何异常都不阻断 CLI 启动。
- 默认动画 `default`：左侧 11 行块状像素 `α`，右侧三行半块字标 `AAA`，下方 `v版本` 与项目全称，整组按终端列数居中。动效对齐 omp：品红 → 紫 → 青的斜向渐变以 ease-out 旋转 2.5 圈，一道白色高光独立扫过 3 次并淡出，末帧落回静止渐变。30fps 采样，总时长取 `ui.banner_duration`（默认 3 秒）。至少需要 40 列、12 行；空间不足时显示单行标题。
- 可选动画 `sharingan`：三阶段写轮眼素材内嵌于 `cli/animations/sharingan.py`，用半块字符按原始 56×56 色点输出 56 列 × 28 行，静态圆内保留原色，不依赖专用图片协议。圆外使用默认终端背景；边缘半格只给圆内部分着色。
- 写轮眼在左、彩色像素字标 `AAA` 在右，每个 A 的右笔多延伸一行。字标和版本之间空一行，项目全称紧接版本下一行；整组按终端列数居中。该动画声明至少需要 86 列、31 行；不足时宿主只显示单行标题，不缩小图案。
- 写轮眼动效按比例分配：停留 4%、旋转 19%、变形 40%、脉冲 15%、淡化 22%，总时长取 `ui.banner_duration`。三勾玉慢转到 55°；内圈黑纹按与起始黑纹的距离向万花筒的六瓣间隙扩展，末段对齐现有佐助万花筒素材；变形帧平均四个子像素样本，圆框不转动。脉冲与淡化共用一条同向转速曲线，结束直接绘制正位的永恒万花筒。
- 动画用独立的内联渲染区，不读取键盘、不清屏，正常结束只保留终态。播放中空间不足时停止并显示单行标题，不回收终端已重排进滚动历史的帧。支持 256 色和真彩交互终端；已知低色、禁色和 `TERM=dumb` 只显示文字标题。POSIX 参考终端颜色能力，Windows 使用 `prompt_toolkit` 的原生输出能力，不要求 `TERM`。支持彩色但关闭动画时直接显示终态。
- 选择与预览：`/config start` 直接弹动画选择器（发现结果，`↑↓` 选择、`Enter` 确认、`Esc` 返回），`/config start <动画名>` 是等价快捷路径；`ui.banner_animation` 的修改都走同一列表，未知名字报错而不是静默回落。修改下次启动生效；`python -m aaa.cli.banner --animation <名或路径> --duration <秒>` 单独预览，动画文件出错时打印 traceback 并返回 1。

### 状态条与正文

编辑器和状态行是一个内联输入区，两行紧贴。上行按 `标识 → 模型 → 目录 → Git → 花费 → 上下文` 排列；下行左侧用转角提示符，右侧显示当前可用快捷键，有碰撞时隐藏。运行、停止和排队提示按需出现在输入区上方。

- Git：分支（detached 显短提交号）、已跟踪改动与未跟踪文件数；只读 `git status --porcelain=v1 -z --branch`，异步按 `ui.git_interval` 刷新，超时隐藏并记日志。
- 花费：当前会话已获得的可计价用量，切换会话时重置显示；没有金额时隐藏，不冒充 `$0.00`。
- 上下文：已知窗口时显示容量；百分比和占用条仅由实际 token 统计产生。
- 宽度按终端显示列计算；缩窄时先压缩目录、隐藏 Git 明细与上下文图形，必要时省略次要字段。
- 正文渲染 Markdown 标题、列表、引用、代码块与行内代码，代码块着色。
- 工具行显示名称、目标摘要、状态与耗时；结果默认折叠为一行摘要，完整内容用 Ctrl-O 查看。
- diff 含文件头、行号、`+/-`、红绿行级颜色与配对行词级反显；无颜色时保留符号与行号。

### TODO 树形任务区

- 位置在输入区上方；标题 `TODO`，阶段标题旁显示 `完成数/总数`，子任务用树线连接。
- 当前任务加醒目标记与强调色；完成项绿色勾选、弱化并加删除线；待办用中性色；无颜色/无删除线终端靠标记区分。
- 默认只展开当前阶段；当前阶段由显式进行中任务决定，没有进行中任务时以第一个未完成任务的阶段为焦点，不伪标进行中；全部完成时展示最后阶段。
- 任务文字按显示宽度折行；高度不足先折叠非当前内容，保留当前任务与隐藏提示，且不挤占编辑器、审批区与工具详情。
- `/todos` 输出按阶段分组的完整只读清单，编号全局一致。
- 任务变化、终态与切会话时刷新；空清单隐藏常驻区域。刷新不清草稿、不移动光标、不抢审批按键。

## 三、交互键位

按键语义只按「当前层级」判定，补全菜单、审批和普通草稿共用同一套。

| 操作 | 补全菜单打开 | 审批待决 | 普通草稿 |
|---|---|---|---|
| ↑ / ↓ | 移动菜单选择 | 在「批准 / 拒绝」间移动 | 历史记录 |
| Enter | 已用 ↑↓ 选中时接受；命令名随后提交，参数与 `@` 文件只插入 | 确认选中项（挂载 500ms 后生效）；草稿非空时改判「拒绝并发送」 | 空闲提交；运行中加入 FIFO 队列 |
| Tab | 接受补全但不提交 | — | 补全 |
| Esc | 关闭补全 | 拒绝 | 收起工具详情；运行中请求取消 |
| Ctrl-C | 清草稿并允许 Up 取回 | 草稿非空先清空，否则拒绝 | 首次清草稿并允许 Up 取回；窗口期内再次按下退出 |
| Shift+Enter | 插入换行，绝不发送 | 插入换行 | 插入换行 |
| 多行粘贴 | 一次进入草稿，内容中的回车不执行 | — | 同左 |
| Ctrl-D | — | — | 仅空闲空草稿退出 |
| Ctrl-G | — | — | 用 `$VISUAL`/`$EDITOR` 编辑草稿，失败保留原稿 |
| Alt+Up | — | — | 从当前会话的暂停队列取回最近一条；草稿非空时不覆盖 |
| Ctrl-O | — | — | 展开/收起最近一次工具的完整参数与结果；不改变输入焦点 |
| PgUp / PgDn | 菜单翻页 | — | 工具详情展开时按页滚动 |
| Shift+Tab | — | — | 空闲循环权限模式；运行中拒绝 |
| /exit | — | — | 有运行先取消并等待实际结束，再释放资源退出 |

- 审批不需要额外聚焦键：审批区出现即接管 ↑↓/Enter/Esc，草稿仍可输入；新审批挂载 500ms 内不接受确认键，防止误放行。
- 补全菜单打开时 ↑↓ 永远优先于历史；命令名只按输入文本提交，不会因补全刷新而误执行参数。
- 退出等待期间显示真实状态，不用超时杀工作线程。
- Ctrl-C 清行/二次退出与 Esc 取消是两件事。

### 修饰键协议

终端默认不区分 Shift+Enter：两者都发同一个 CR。CLI 在会话启动时对已实现 xterm `modifyOtherKeys` 的终端（iTerm2、WezTerm、ghostty、VS Code；tmux 内还需 `extended-keys` 与外层终端支持）写 `ESC[>4;2m`，正常退出与 Python 异常都写 `ESC[>4m` 还原；进程被信号杀死时不还原。不在名单内的终端保持原样（kitty 不实现该协议，尚未接入），需用户自行映射。

开启后终端把所有带修饰键的按键重新编码为 `ESC[27;<mod>;<cp>~`（Kitty 为 `ESC[<cp>;<mod>u`），prompt_toolkit 3.0.53 几乎不认。`cli/key_input.py` 在字节层把它们还原成既有绑定认得的传统字节：Ctrl+字母与 Ctrl+`@ [ \ ] ^ _`/数字 → 控制字节（含 Ctrl+[ 即 Esc）、Shift+字母 → 大写字符、Alt+字母 → `ESC`+字符、Backspace（码 8/127）→ `DEL`（Alt 加 `ESC` 前缀，走 backward-kill-word）、Shift+Tab → `ESC[Z`；Ctrl+Shift+Tab 等同 Tab，不改权限模式。Super/Meta 组合、Kitty 松键事件与无法表示的组合被吞掉，避免原始序列泄漏成字面文本。Shift/Alt/Ctrl+Enter 在同一批输入内归一为携带原始序列的换行标记（`KeyPress.data`），`enter_action` 与审批的 Enter 据此只插入换行、绝不提交或授权；Esc 与紧随其后的回车分属两次读取时保持「先取消、再提交」，不融合成换行。Bracketed paste 内容不翻译。代价是 Option+字母 在开启后按 Alt 语义处理，不再输入组合字符。

主草稿、补全菜单、选择器与命令表单共用同一条适配后的输入流，键位语义一致。

### 输出期间的命令

所有提交先解析为普通消息、内置命令或自定义命令；队列消费重走同一分派器，不把 `/…` 当文本发给模型。

- 普通消息和自定义提示词命令：FIFO，快照保存文本、附件与来源会话。
- `/exit`：立即进入退出流程，不排队。
- 只读且不弹菜单的 `/help`、`/todos`、`/usage`、`/skills` 与 `/memory`（运行中只显示状态）：由 UI 调度显示，不触碰活动 Agent。
- `/new`、`/compact`、会话切换、模型/权限切换、`/redo`、`/edit`、`/memory` 的引擎菜单、配置修改、插件启停及其他交互菜单：运行/审批/停止时拒绝并提示空闲后重试，未分类命令默认拒绝。
- 取消后不自动发送排队消息；队列原样保留供取回。正常完成才自动派发下一条；失败后暂停队列并显示原因。

### 命令交互形态

- **有界选择集的命令必须同时提供两种等价路径**：裸命令弹多级菜单（引导路径），带参数直达同一动作（快捷路径），两者效果一致。现状符合：`/config`、`/memory`、`/model`、`/session`、`/plugin`；`/export` 裸命令确认预填路径。
- **空闲命令菜单统一由 `cli/picker.py` 渲染**：`❯` 前缀 + 主题强调色、无背景色块，`↑↓` 移动、输入即筛选、`Enter` 确认；`Esc` 返回上一级，根层 `Esc` 取消，`Ctrl-C` 放弃整个命令。选择器在独立循环运行，不嵌套主 REPL 事件循环。首次启动与 `/provide` 的渠道向导继续用 questionary 承载密码、多选等表单，只有其中的选择列表可逐步迁移。
- `/config` 的有界值直接渲染选择器：`Key.choices`、布尔值 true/false、`ui.banner_animation` 的动画发现列表；其余值才进入文本输入。未知动画名报错，不静默回落。
- **自由文本与单动作命令不做菜单**：`/edit`、`/image` 的内容是用户输入；`/redo`、`/compact`、`/new`、`/exit` 只有单一动作；`/todos`、`/skills`、`/usage`、`/help` 是只读展示，套菜单是噪音。
- 命令清单（补全菜单与 `/help`）按使用频次排序：次数降序优先，同次数按字母 A→Z；频次账本是本地 `~/.aaa/command_usage.json`，损坏或缺失回退字母序，用户自定义斜杠命令一并参与。新增命令按本准则选择形态。

## 四、薄契约与所有权

Agno 拥有执行点；CLI 只改调度、事件投影与审批通道，不改授权规则、签名缓存或插件信任政策。

| 拥有者 | 持有与写入 |
|---|---|
| `AppState` | 会话、选模、权限、配置、主 Agent、扩展发现结果；只由 UI 调度线程改变 |
| `Controller` | 当前运行、生命周期、队列、审批选择状态、退出意图；单个 UI 事件循环串行修改 |
| `run` 工作线程 | 消费 Agno 原生迭代器，发布视图事件；不读终端、不改界面 |
| `ui` / `tool_details` | 主屏布局、样式、宽度与最近工具详情；不装配 Agent、不写会话库 |
| Agno / usage | 保存会话与运行；usage 拥有金额与账本，CLI 只读显示 |

- 运行记录结构：`token + session_id + run_id（可空）+ cancel_requested`；阶段 `idle → starting → running ↔ approval → stopping → idle`。
- 取消请求与取消完成分开：只有收到原生取消终态才算已取消，否则如实报告未确认。
- 视图事件按 **call id** 对应工具调用，不按工具名合并；工作线程经 `loop.call_soon_threadsafe` 投递。
- 工具详情只保留最近一次调用：`tool_start` 选中新调用并复位滚动，结束事件必须与保留调用的 `call_id` 一致（双方都无 id 时才按名称回退），陈旧完成不能覆盖新调用。展开状态不改变输出历史。
- 正文、终态、取消和审批续跑来自原生 Agent run。Agno 日志只落文件，保证 JSON 输出为纯 JSONL。

### TODO 数据与显示契约

- 唯一事实源是 `RunContext.session_state["todos"]`，Agno 随会话保存；CLI 只持显示快照。
- 规范条目：`{"text": str, "phase": str | null, "status": "pending" | "in_progress" | "completed"}`；完成数由 status 推导，同一会话最多一个进行中。
- 旧 `text/done` 条目在入口归一，不虚构进行中状态，不批量改库。
- 工具：`todo_add(items, phase=None)`、`todo_start(index)`、`todo_done(index)`、`todo_list()`；开始一个待办会把原进行中项转回 pending；越界或重复操作返回错误且不改清单。
- 工具统一返回 JSON `{"ok","message","todos"}`；CLI 仅在 ok=true 时用结果快照刷新，失败保留原快照。

### 主屏渲染

- 单终端读写拥有者：稳定输出进入终端滚动历史，未完成的 Markdown 块留在缓冲；状态、正在编辑的草稿、审批和工具详情在活动区重绘，提交时不把状态行写进历史。
- Rich 只作 Markdown/Text 格式化器；模型、工具和 diff 文本经 `render.sanitize`。只有格式化器生成的样式交给终端绘制，普通 stdout 不开启 raw。
- 主布局按实际终端行数与草稿渲染高度分配：TODO、工具详情、审批、活动提示、状态行、编辑器。保留一行滚动余量，长草稿在编辑器内滚动；补全仅在有候选且编辑器有焦点时占用预算。窄窗优先压缩辅助区，打开工具详情时先收缩 TODO。终端在 resize 时自行重排行，不回收其已保留的旧活动行。
- 空闲菜单（`/model`、`/mode`、`/config`、`/memory` 等）由 `cli/picker.py` 在独立循环运行，避免嵌套事件循环；`Esc` 逐级返回、根层取消，`Ctrl-C` 放弃整个命令。
- 不完整代码围栏留在活动尾部，闭合后提交；无颜色模式移除样式但不丢文本。

### 持久化与非交互

- `user_id`、channel、session_id 在交互、print、json 与 continue 分支保持一致；显示重构不改变身份、记忆归属或会话生命周期。
- Agno 原生历史是唯一回放来源；不提供清空上下文的命令，也不伪造运行成功或自建回放层。
- print 只输出正文；json 保持既有事件协议，无横幅、ANSI、Git 与交互审批。
- 退出码：成功 0、运行失败 1、用法/配置 2、被 Ctrl-C 取消 130。

## 六、保留边界

- 会话管理、导出、图片、选模、权限、`/compact`、`/memory` 与 `/config` 继续经现有入口。
- 命令模板 `~/.aaa/commands/<name>.md`、MCP 扩展 `~/.aaa/extensions/`、技能目录与随包技能保持发现与重启约定。
- 非交互默认拒绝需确认操作；`--allow-shell` 仅放行 `run_shell_command`。

## 七、`/memory`

`/memory` 空闲时显示当前记忆引擎与条目数，并弹出操作菜单（切换引擎；外置引擎附「引擎配置」）。`/memory engine [引擎]` 直达切换，跳过菜单。`/memory config [键] [值]` 编辑当前外置引擎的配置面（引擎经 `config_specs()` 声明、`apply_config()` 落盘，写引擎自己的配置文件，重启生效；密钥遮蔽显示）。`/memory embedding [install]` 安装/查看嵌入增强。运行中只显示状态，不弹菜单。记忆引擎互斥：启用外置时不启用内置。
